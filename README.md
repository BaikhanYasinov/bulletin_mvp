# Структура

```
bulletin_mvp/
  app.py                  # Flask-приложение (веб-интерфейс)
  main.py                 # CLI-запуск генерации (без веб-интерфейса)
  bulletin/
    config.py             # расписание, получатели (пока не используется), пути
    data_source.py         # источник данных — планируется заменить на реальный БД/API
    charts.py               # график тренда выручки (matplotlib)
    generator.py             # сборка контекста бюллетеня
    render_html.py            # рендер HTML по шаблону (Jinja2)
    render_pdf.py              # рендер PDF (reportlab)
    actions.py                  # generate_now() — общая точка входа для CLI и Flask
    templates/bulletin.html      # шаблон самого бюллетеня
  templates/index.html            # шаблон архива (страница Flask)
  output/                          # сюда складываются готовые бюллетени (создаётся сама)
```

# Запуск (веб-версия)

```bash
pip install -r requirements.txt
python3 app.py
```

Открыть http://127.0.0.1:5000 — кнопка "Сформировать бюллетень сейчас"
генерирует новый бюллетень и добавляет его в архив на той же странице.

# Запуск (CLI, без веб-интерфейса)

```bash
python3 main.py
```

# При переходе в прод

1. **Данные**: заменить `data_source.get_weekly_kpis()` на реальный запрос
   к БД/API/BI-хранилищу — структура возвращаемого словаря должна остаться
   такой же, тогда остальной код трогать не придётся.

2. **Расписание**: сейчас генерация только по кнопке. Варианты для реального
   еженедельного запуска:
   - системный cron раз в неделю, который бьёт `curl -X POST .../generate`;
   - отдельный воркер/скрипт (`main.py`) по cron, без Flask вообще;
   - фоновый планировщик внутри приложения (APScheduler и т.п.) — потребует
     установки пакета.

3. **Доставка**: добавить в `actions.generate_now()` (или отдельным шагом
   после него) отправку письма через SMTP/SendGrid с PDF во вложении и
   ссылкой на HTML-версию. Список получателей уже вынесен в `config.RECIPIENTS`.

4. **Права доступа**: если бюллетень персонализирован по ролям/фильтрам,
   нужно параметризовать `build_bulletin()` получателем и генерировать
   отдельный файл на каждого (или на группу с одинаковыми правами).

5. **Продакшн-сервер**: `app.run()` — только для разработки. Для реального
   использования — gunicorn/uwsgi за nginx.
